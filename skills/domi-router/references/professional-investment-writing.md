# 专业投研正文与必要归因

适用于结构化纪要、公司／行业研究、基本面分析、投资快评和IC报告。写作和最终编辑前完整读取；当前任务已读过同一版本时复用。这里只统一正文表达，原有来源、全文覆盖、研究深度和事实校验要求继续执行。

## 直接呈现信息

- 以公司、产品、客户、业务动作、指标、技术机制或投资问题组织正文。段首先给出这一段最有信息量的事实或有证据的判断，再展开数字、机制、案例、条件和结果；不按受访者或检索来源依次拼接摘要。
- 去掉不承担信息的发言框架：`某某介绍／回忆／提到／表示`、`据其所述／据其介绍`、`交流中谈到`、`报告指出`。把句子的主语还给实际发生业务、承担责任或作出判断的主体。不要把这些词统一替换为“公司称”“据悉”“据了解”“其表示”，也不改用被动句掩盖归属。
- 人物承担真实业务角色时直接保留姓名及动作，例如“李某于2019年加入甲公司，负责搜索排序”。人物履历、技术贡献、组织责任、产品决策和交易参与关系不得因去掉发言框架而消失；`参与／主导／负责／提出`等责任强度不得互换。
- 信息密度来自减少重复和无增量语句。不得按字数、压缩比例、每节条数或人名出现次数裁剪；关键数字、单位、期间、分母、案例过程、失败原因、反证、条件和因果链必须覆盖。表格适合比较，正文承担解释，不把同一材料再完整复述一遍。
- 用具体事实替代泛化评价：写清成本下降多少、哪一环节受限、哪个指标变化、为何影响判断，去掉“优势显著”“前景广阔”“值得持续关注”等没有支撑的结论。专业感来自可核验的信息和清晰推理，不靠行话、强势语气或增加免责声明。

## 让归因承担实际作用

先在内部证据记录中完整保存`谁提供信息／谁执行动作／谁作出判断／数据来自何处／截至时间／证据状态`，再决定正文需要显示什么。来源身份和业务主语是两回事，不能通过删除前者而误改后者。

| 情况 | 正文处理 |
| --- | --- |
| 单一对象的事实、产品流程、已明确的履历 | 直接使用业务主体和动作；去掉“介绍／回忆”等发言外壳。按原交付规则保留来源，不暗示已独立验证。 |
| 公司自报的重要经营数字、性能、排名、内部最新进展 | 在相关事实组中保留一次明确的“公司口径”，或在该表的口径列／紧邻引用中交代。范围须清楚；跨章节、换来源或混入核实数据时重新标清，不依赖远处的全篇免责声明。 |
| 计划、预测、估算、假设、目标 | 保留相应状态词、提出主体及成立条件；目标、预测和已实现结果不能互换。管理层预测和分析者模型假设须分别标明。 |
| 主观判断、关键反证、观点分歧 | 以争论的问题为中心合并呈现，简短写清各方判断及依据。只有归属会改变含义时才保留发言动词；不得把不同人的判断合成虚假的共识。 |
| 客户反馈、专家意见、行业传闻或第三方转述 | 保留到足以区分来源的主体与证据距离，如“客户测试反馈”“管理层转述的客户反馈”。不能把转述改成直接访谈，把单一样本升级成全体客户结论。 |
| 历史经历、多期资料、数字冲突 | 保留实际时间和对应口径；未消解冲突在相关事实旁表达一次，不附审计过程或冲突总表。 |
| 有意义的直接引语 | 仅在原话措辞本身承载承诺、独特判断、争议或关键定义时引用，并保留原有来源。普通业务事实改为间接陈述。 |

同一事实组的归因不逐句重复。表格标题、口径列或紧邻引用已清楚说明来源时，不再逐项添加“（公司口径）／（管理层披露）”括号。公司、受访者或来源改变、段落可被独立摘引、存在重要数字或争议时，优先让局部语境足以准确理解。引文、来源链接、日期、表格口径与内部证据记录按原任务要求保留；不能为了正文简洁删除研究报告的实质引用，也不把来源标签、置信度字段和审计动作机械搬成正文。

## 按交付物组织

- **纪要**：按主题归并本次交流已有的事实、机制、案例和判断，保留重要问答之间的联系。允许改变句式和组织顺序；不因追求投研风格新增分析结论、因果解释或尽调建议。模式A／B各自的内容选择及行动项规则继续执行。
- **研究与IC报告**：以投资问题及有证据的核心判断组织主线，将不同来源按同一指标和时点交叉比较。由事实解释机制、经济影响、成立条件及反证；区分事实、管理层预期和研究推断，不把创始人叙事直接当作投资结论。数据不足时指出影响结论的具体缺口，不罗列通用材料清单。逻辑链按内容需要展开，不把“事实→机制→含义→反证”四个标签机械填满每段。
- **增量修改与归档**：只重写授权范围内的正文，复用仍有效的来源和证据。改写后检查事实、主语和引用是否仍对应；按原流程更新受影响的正文落点、哈希和QA。归档、格式化、导出环节复用已审正文，不重新添加发言套话、审计说明或新分析。

## 匿名写法示例

| 原表达 | 编辑后 |
| --- | --- |
| 创始人张某介绍，公司上半年签约金额3,000万元。据其所述，已确认收入2,000万元，回款1,500万元。 | 上半年签约金额3,000万元，确认收入2,000万元、回款1,500万元（公司口径）。 |
| 李某回忆，自己2019—2022年在甲公司任算法负责人，参与搜索排序重构。 | 李某：2019—2022年任甲公司算法负责人，参与搜索排序重构。 |
| CEO王某介绍，公司预计明年收入约5,000万元，但要等两家客户验收。 | 管理层预计明年收入约5,000万元，前提是两家客户完成验收。 |
| 王某表示产品适用于大客户；客户乙认为当前权限管理不能满足其部署要求。 | 大客户适用性存在分歧：王某判断产品适用；客户乙认为当前权限管理不满足其部署要求。 |
| 管理层介绍，渠道商反馈三家客户愿意试点。 | 渠道商反馈有三家客户愿意试点（管理层转述）。 |

以上仅示范表达调整。每次仍须核对实际原文；不得把示例事实、状态或判断套到真实项目。

## 交付前编辑验收

1. 去掉发言框架后，每段是否仍有明确业务主体？参与、主导、转述和判断是否归属准确？
2. 是否仍按人物／来源拼接，或把“某某介绍”换成另一种套话？有依据的同主题内容能否整合得更直接？
3. 重要数字是否保留单位、期间、分母和公司自报等必要口径？预测、目标、假设和已实现结果是否区分？
4. 对照输入的信息清单，重要机制、案例步骤、数字、反证与限制是否均有实际落点？不要用“已概括”代替完整覆盖。
5. 纪要是否混入模型新增判断？研究报告是否有证据支持判断和因果，是否保留影响结论的反例及来源？
6. 原引用与内部定位是否仍对应最终句子？没有通过删主语、删限定、隐藏冲突或提高语气确定性制造专业感？

验收在内部完成，不把这张清单或改写过程附在交付正文。格式器和关键词扫描不能代替语义编辑，不按人名或发言词批量删句。
