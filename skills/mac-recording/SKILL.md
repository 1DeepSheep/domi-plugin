# Mac Recording

使用 macOS 原生 AVFoundation 在后台录制默认麦克风。录音进程由 Codex 直接启动后独立运行，可在当前命令结束后继续；一次只允许一个活动录音。停止录音通过私有、带会话令牌的控制文件完成，不依赖 PID 发信号。

本 Skill 只录制麦克风，不录制系统音频、屏幕或远端会议应用的内部声道。

## 入口

从本 `SKILL.md` 所在目录解析：

```text
scripts/mac-recording.js
```

用 `node <resolved-script-path> <command> ...` 调用。所有命令在 stdout 返回 JSON；根据 JSON 字段判断结果，不从日志猜测状态。

当前已采用的本 `SKILL.md` 所在目录是唯一解析根目录。不得用 `find`、`rg`、目录枚举或版本比较寻找其他源码／插件缓存副本；入口缺失时立即报告，不转而搜索其他副本。

| 命令 | 行为 |
|---|---|
| `doctor` | 检查 macOS、Swift、AVFoundation helper 和当前麦克风权限；不请求权限、不启动录音 |
| `status` | 查询是否正在录音、已录时长和输出路径 |
| `start [--out-dir DIR] [--name NAME] [--duration-seconds N] [--workflow-kind quick-discussion]` | 请求必要的麦克风权限并开始录音；可原子绑定快速讨论工作流 |
| `stop` | 让录音进程正常停止并封装 M4A 文件 |
| `last` | 读取最近一次已完成或失败的录音结果 |

`start --dry-run` 只用于开发验证，不请求权限、不启动录音。

## 授权边界

- 只有用户当前消息明确要求立即开始录音时才运行 `start`。“能录音吗”“之后帮我录”“会议快开始了”不构成启动授权。
- “现在开始录音”“开始录下这段会议”已经是明确授权，不要重复确认。通过 domi 路由时，这类无修饰启动同时选择快速讨论完整工作流；明确的本地限定除外。
- 启动授权只对本次录音有效，不得从历史对话、日历、自动化或环境状态推断或复用。
- 不得因为用户沉默、任务结束或离开对话而自动停止；只有用户明确要求停止，或用户预先给出的时长到达后才停止。
- 不得隐藏 macOS 麦克风指示、规避权限提示或声称录音已开始，除非返回 JSON 明确包含 `recording: true`。
- 简短提醒用户确保已经取得适用场景下所需的参会人知情与同意；不要把提醒变成重复阻塞确认。

## 开始录音

1. 若用户没有明确要求立即开始，只回答能力；只有用户明确要求诊断或检查环境时才运行 `doctor`。
2. 用户明确开始时，只执行一次 `node <resolved-script-path> start ...`；支持串行工具编排时，把读取本文件与随后执行 `start` 放在同一次工具往返中。不得在其前后运行 `doctor`、`status`、`last`、`--dry-run` 或额外 shell 预检。默认输出到：

   ```text
   <当前工作区>/work/domi/mac-recording/<时间戳>-<session-id>/<时间戳>-local-mic.m4a
   ```

3. 用户给出名称时传 `--name`；给出时长时换算为秒并传 `--duration-seconds`；给出目录时传绝对 `--out-dir`。
   - 通过 domi 执行无修饰的“开始录音／现在开始录音／启动 Mac 录音／录下这段讨论”时，默认传 `--workflow-kind quick-discussion`。CLI 会在同一次启动中生成并持久化 `workflowId`。
   - 只有用户明确要求“开始本地录音／仅本地录音／只录音不上传或不整理／停止后只保存文件”时才省略该标签。不要为确认默认分流增加一次问答。
4. 第一次使用可能出现 macOS 麦克风权限框。只有 `start` 可以触发该提示；`doctor` 和 `status` 不得触发。
5. JSON 明确返回 `recording: true` 后立即报告：已开始、绝对输出路径、开始时间、自动停止时长（如有）和 `timings.totalMs`，并说明用户可说“停止录音”。快速讨论同时保留返回的 `workflowKind/workflowId` 供停止后的后续流程识别。不得在回复前执行测试、插件更新或其他后置工具调用。

若返回 `ALREADY_RECORDING`，不得启动第二个；直接使用本次错误详情报告当前录音路径和已录时长，不再运行 `status` 或重试。正常启动热路径只允许一次调用；只有 `start` 返回其他错误时才进入只读恢复或诊断。

## 停止与状态

- “录音状态／还在录吗／录了多久” → 运行 `status`。
- “停止／结束／保存录音” → 运行 `stop`，等待停止回执与正常封装完成；不要自行使用 `kill`、`pkill`、进程名匹配或 `SIGKILL`。
- `stop`、`status` 和 `last` 返回的 `workflowKind/workflowId` 必须原样交给上游。若为 `quick-discussion`，只负责交付已校验音频，不在本 Skill 内自行上传 PLAUD。
- `stop` 成功后必须同时确认终止回执存在，且 `audioPath` 存在、非空并通过系统音频文件校验，再向用户报告保存路径和时长。
- `stop` 可重复调用；已完成时直接返回同一录音的终态，不得再次发出停止请求。
- 若 `stop` 返回错误，先立即运行一次只读 `status`，再读取 `last`：若已成功封装，则按成功报告并把首个错误仅作为诊断信息；只有恢复检查仍未完成时才向用户报告失败。
- 若返回 `COMMAND_IN_PROGRESS`，短暂等待后运行 `status`/`last` 取得同一会话终态，不要把并发命令误报成录音失败。
- 若录音已按预设时长自动结束，`status` 或 `stop` 应返回已完成文件，而不是把它误报为未录音。

## 权限与错误

- 权限为 `not_determined`：只有明确的 `start` 才请求。
- 权限为 `denied/restricted`：停止重试，告诉用户前往“系统设置 → 隐私与安全性 → 麦克风”允许 domi Mac Recording（部分系统可能显示为 Codex）；用户修复后需再次明确开始。
- helper 编译、启动或封装失败：报告返回的 `code`、简短错误和保留的日志／partial 文件路径；不得声称成功。
- 只有带正确会话 ID 与令牌的停止请求、预设时长结束或 recorder 正常完成才可记为成功；外部 `SIGINT/SIGTERM` 只用于尽量保全音频，必须标记为中断而非成功。
- 发出停止请求前，状态文件与实际进程身份（PID、用户、可执行文件、会话令牌、输出路径及启动时间）不一致时，拒绝控制未知进程，报告为 stale/unsafe。
- 停止请求发出后，进程进入僵尸态、退出或 PID 被复用都表示原录音进程已结束；不得再次控制该 PID，应转入终止回执和音频文件校验。

## 输出与 ASR Notes 交接

录音为单声道 AAC `.m4a`。状态目录和停止控制目录权限为 `0700`，音频、状态、日志与停止请求文件为 `0600`。不要写入插件目录。

带 `workflowKind=quick-discussion` 的录音停止后，把绝对 `audioPath`、`workflowId` 以及用户已提供的对话背景、参会人信息原样交给 `domi-router`，由其继续 PLAUD 和纪要流程。没有工作流标签的明确本地录音只交付录音路径；仅在用户另行要求转写或整理时再采用相应 Skill。
