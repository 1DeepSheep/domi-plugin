# Mac Recording（旧版恢复）

本 Skill 只负责收尾旧版 domi 已经启动的 Mac 麦克风录音，避免客户端升级后留下无法停止或无法取回的录音。它不再提供新的录音启动能力，也不负责上传 PLAUD、整理纪要、录制屏幕或系统音频。

用户明确要求发送、下载或查看已安全封装的实际音频文件时，完整读取并执行[跨客户端真实附件交付](../domi-router/references/artifact-delivery.md)；必须先完成音频完整性校验，不得只返回本机路径、source link 或原始内部文件指令。

## 入口

从本 `SKILL.md` 所在目录解析：

```text
scripts/mac-recording.js
```

用 `node <resolved-script-path> <command>` 调用。所有命令在 stdout 返回 JSON；根据 JSON 字段判断结果，不从日志猜测状态。不得用 `find`、`rg`、目录枚举或版本比较寻找其他插件副本。

只允许使用以下兼容命令：

| 命令 | 行为 |
|---|---|
| `status` | 查询旧版录音是否仍在进行、已录时长和输出路径 |
| `stop` | 正常停止旧版活动录音并封装 M4A 文件 |
| `last` | 读取最近一次已完成或失败的录音结果 |

底层脚本为旧版本恢复保留了其他实现细节，但本 Skill **绝不得调用 `start`、`doctor` 或 `--dry-run`**。用户说“开始录音”“现在录下这个会议”时，明确说明 domi 已不提供启动录音，请使用 PLAUD 或其他录音设备；不得把它解释为 quick discussion，也不得创建新的录音状态。

## 停止与状态

- “录音状态／还在录吗／录了多久” → 运行一次 `status`。
- “停止／结束／保存录音” → 运行 `stop`，等待停止回执与正常封装完成；不要使用 `kill`、`pkill`、进程名匹配或 `SIGKILL`。
- `stop`、`status` 和 `last` 返回的 `workflowKind/workflowId` 必须原样保留。若旧录音带有 `quick-discussion` 标记，它只表示历史兼容状态，不授权启动新录音。
- `stop` 成功后确认终止回执存在，且 `audioPath` 存在、非空并通过系统音频文件校验，再报告保存路径和时长。
- `stop` 可重复调用；已完成时直接返回同一终态，不再次发出停止请求。
- 若 `stop` 返回错误，立即运行一次只读 `status`，再读取 `last`；若已成功封装则按成功报告。
- 若返回 `COMMAND_IN_PROGRESS`，短暂等待后用 `status`/`last` 取得同一会话终态。

## 安全边界

- 不请求新的麦克风权限，不隐藏 macOS 麦克风指示，不声称已开始新录音。
- 状态文件与实际进程身份（PID、用户、可执行文件、会话令牌、输出路径及启动时间）不一致时，拒绝控制未知进程。
- 外部 `SIGINT/SIGTERM` 只用于尽量保全音频，必须标记为中断，不能记为成功。
- 状态目录和停止控制目录权限为 `0700`；音频、状态、日志与停止请求文件为 `0600`。不要写入插件目录。

## 旧录音交接

旧录音停止后，只报告经过校验的绝对 `audioPath`。如果用户明确要求继续整理，可把这个既有音频交给 `asr-notes`；若历史状态带有可恢复的 `quick-discussion` 工作流标记，可交给 `domi-router` 继续原工作流。任何交接都不得重新启动麦克风或新建录音。
