# domi 外部交付通道契约

domi 的权威资料库始终是本地 SQLite + Markdown + 附件目录。`delivery_only=feishu_doc|feishu_dm` 只是把本轮结果额外交付到飞书，不写回 `storageBackend`，不改变固定的 `repositoryBackend=local`。

## 1. 触发与边界

只有用户明确说“创建／更新飞书文档”“发到飞书文档”“推送到我的飞书私聊”“发给某人的飞书私聊”等，才设置对应 `delivery_only`。仅说“研究”“整理”“入库”“归档”不能推断外部交付授权。

外部交付不得：

- 创建或迁移项目、人脉、行业动态 Base；
- 要求 Base Token、Table ID 或固定 Wiki Space ID；
- 把飞书副本当作权威项目主页／人物主页／待办事项文档；
- 删除、移动或覆盖本地 SQLite、Markdown、图片或附件；
- 因飞书失败重复研究或重复本地入库。

## 2. 飞书文档

`delivery_only=feishu_doc` 兼容创建和编辑：

1. 完整执行 [feishu-knowledge-extension.md](feishu-knowledge-extension.md)。普通新内容／目标文档编辑采用 `lark-doc`；现有本地 Markdown 的整篇保真搬运必须交给 App host，模型不接收写凭证。
2. 没有目标文档时创建普通飞书云文档；提供目标并明确编辑时，对目标做最小范围更新，不新建近似标题副本。
3. 用户明确指定 Wiki／文件夹才放入该位置；目标有歧义时让用户选择，不要求预绑定 Wiki Space。
4. 源为本地 Markdown 时必须保留结构、链接、表格、代码块与图片位置，并执行写后回读清单；任一内容丢失只能报告 `partial`。
5. 飞书文档是外部副本。本地源仍可独立编辑，不建立隐式双向同步。

## 3. 飞书私聊

1. 完整采用 `lark-im`。发送给“我”时解析为当前已登录用户；指定他人时先唯一解析收件人，同名或多候选必须确认。
2. 内容过长时不能暗中改成飞书文档；询问用户缩短发送，还是另行授权 `feishu_doc` 并发送链接。
3. 写前明确目标收件人；不得依据历史聊天猜测。
4. 发送后验证成功，默认报告不展示用户标识、会话标识或消息 ID。

## 4. 授权失败与恢复

- 未登录或授权过期：请用户连接／重新连接飞书账号，从当前交付阶段恢复。
- 权限不足：说明缺少文档或消息权限，不得改口要求资料库 Base／Wiki 配置。
- 飞书不可用：保留本地结果和交付状态，不切换权威源，不重复生成内容。
- 鉴权失败不能静默切换身份、机器人或其他用户账号。

## 5. 幂等与隐私

- 创建／发送使用 `workflowRunId + channel + target + contentHash` 作为幂等键；编辑增加目标文档标识和操作类型。状态不确定时先查询，不得直接重建、重写或重发。
- 账号、文档 token、空间标识、消息 ID、会话 ID、授权凭据和本机路径只作为本机运行数据，不写入 Skill、Git、研究正文、公开日志或诊断包。
- 默认只报告“飞书文档已创建／更新”或“飞书私聊已发送”及必要链接。
