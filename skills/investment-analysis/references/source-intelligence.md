# 投资研究的信息来源与证据质量

用于公司基本面、市场争议、行业链、专家访谈和另类数据的信息搜集与判断。目标不是累计链接，而是围绕关键未知数建立可追溯、可反驳、能进入模型的证据链。

## 1. 从决策问题开始搜索

先建立问题树，不从网站清单开始：

```text
核心投资争论
→ 承重假设
→ 可观察指标
→ 最适合的证据来源
→ 对应模型字段
→ 下一验证事件
```

优先研究“估值敏感度高、当前不确定性高、可被新信息解决”的问题。为每个搜索任务写清：

- 要验证的狭窄命题和反命题。
- 所需实体、地区、产品、客户/供应商层级和时间窗口。
- 希望找到的直接证据、可接受的proxy和不可接受的替代品。
- 搜索截止日期、as-of边界和进入模型的最低标准。

同时做正向和反向搜索。例如验证需求强劲时，必须搜索取消、优化、延期、库存、客户自建、替代产品和价格让步。没有发现反证只有在覆盖范围和检索方法足够完整时才有信息价值。

## 2. 按命题选择来源

来源权威性不能替代命题适配性。按问题选择来源，并明确每类来源的证明边界：

| 问题 | 优先来源 | 可以支持 | 不能单独支持 |
|---|---|---|---|
| 历史财务与会计口径 | 监管申报、审计财报、附注、合同附件 | 已披露历史事实和定义 | 未来需求与管理层判断必然实现 |
| 公司计划与指引 | 财报电话会、IR、投资者日、正式公告 | 公司当时的公开口径 | 独立核实的未来事实 |
| 客户需求 | 客户预算/财报、合同义务、采购记录、使用数据 | 意向、承诺或使用趋势 | 合同上限、订单或backlog等于当期收入 |
| 供应与产能 | 许可、电力/土地/施工、设备订单、供应商披露 | 建设意图和物理状态 | 在建等于投产、可售或已利用 |
| 实现价格 | 历史价目、合同/发票样本、渠道报价、折扣/credits | 特定产品标价或样本成交价 | 全公司ASP和提价收入 |
| 资本开支 | PP&E、在建工程、租赁、采购义务、供应链订单 | 投入、承诺和部分资产状态 | 分部归属、维护/增长属性自动成立 |
| 债务与流动性 | 债券/信贷协议、到期表、评级、债券成交 | 条款、期限、契约和市场风险定价 | 授信额度等于提款、利差等于会计利息 |
| 竞争格局 | 竞对、客户、渠道、监管数据、份额方法说明 | 相对位置和变化方向 | 单方宣传等于全市场事实 |
| 组织能力 | 招聘技能、裁员、关键人员、薪酬KPI | 资源配置方向 | 职位数等于净增员、产能或收入 |
| 产品采用 | API/文档、release notes、状态页、开发者/渠道数据 | 产品存在、迭代和采用proxy | 下载、star、专利等于商业收入 |
| 市场预期 | 有日期的Consensus、修订分布、期权、债券、反向估值 | 市场基线、分歧和风险定价 | 共识等于真实结果或全部buy-side门槛 |

优先取得根文件和结构化原始数据。新闻、社交媒体和搜索摘要主要用于发现线索，必须回溯其引用对象；无法回溯时标为二手陈述。

## 3. 建立来源图与同源去重

不要按URL数量计算独立证据。为每个来源记录血缘：

```yaml
source_id:
title:
publisher_or_subject:
published_at:
observed_at:
retrieved_at:
root_document_id:
root_dataset_id:
interview_subject_id:
methodology_id:
economic_exposure_group:
cites_source_ids: []
source_cluster_id:
```

以下通常只算一个来源簇：

- 多家媒体转载同一公司通稿或匿名爆料。
- 多家券商调用同一个Consensus或行业数据库。
- 多个另类数据商采购同一底层面板。
- 多位专家来自同一公司、部门、客户群或同一时间窗口。
- 产业链上下游都在转述同一客户/公司的需求预测。

优先使用异质三角验证：公司披露 + 经济对手方 + 独立交易/监管/物理观察。两条定义相同但根来源不同的证据，通常比十条同源转载更有价值。

## 4. 使用质量向量评价证据

分别判断，不压缩成一个“可信度总分”：

| 维度 | 判断问题 |
|---|---|
| 原始性 | 原始记录、加工数据、二手分析还是转载？ |
| 直接性 | 直接观察、proxy、推算还是传闻？ |
| 独立性 | 有多少异质根来源，是否存在共同上游？ |
| 代表性 | 样本数、覆盖率、客户/SKU/地区/时间是否适合外推？ |
| 时效性 | 观察、发布、取得时间是否匹配研究期间？ |
| 口径完整性 | 实体、期间、单位、定义和会计口径是否明确？ |
| 利益冲突 | 来源是否持仓、承销、销售、推广或接受报酬？ |
| 可复现性 | 方法、样本和计算能否重做？ |
| 材料性 | 为真时是否显著改变经营、现金、估值或风险？ |
| 增量性 | 市场是否已知道并计价？ |
| 模型连接 | 能否连接具体假设或财务字段？ |
| 合规/权利 | 是否可合法取得、保存、分析和引用？ |

来源可靠性与本条信息可信度必须分开；信息可信度与材料性、增量性也必须分开。官方来源可以准确描述历史收入，却不能单独证明未来需求；单个专家可能很增量，却代表性不足。

## 5. 维护原子命题账本

把复合叙述拆成可单独验证的claim。每条至少记录：

```yaml
claim_id:
claim_text:
entity:
period:
unit_and_definition:
information_identity: actual|guidance|consensus|estimate|observation|calculation|scenario|unknown
supports_or_refutes:
source_ids: []
source_cluster_ids: []
quality_vector: {}
conflicts: []
model_field:
decision_use:
status: verified|company_claim|corroborated|inferred|unresolved|rejected
```

区分“关系存在、方向成立、幅度成立”三种证明强度。一份合同可以证明客户关系，却未必证明收入材料性；价格页面可以证明标价变化，却未必证明实现价格和量价弹性。

所有承重数字保留原文、页码/章节、提取公式和单位换算。计算项引用输入claim_id；不得静默覆盖历史版本或冲突值。

## 6. 完成交叉验证与冲突处理

遇到冲突时按以下顺序处理：

1. 统一法律主体、业务边界、期间、币种、单位和GAAP/IFRS口径。
2. 区分存量/流量、累计/当期、总额/净额、订单/backlog/收入、在建/可售/利用。
3. 回溯根来源，合并同源转载和同底层数据。
4. 判断是真冲突，还是定义、样本、发布日期或经济暴露不同。
5. 历史事实优先使用监管/审计原文；未来判断拆出各自假设，不取机械平均。
6. 无法解决时保留区间或`unresolved`，把不同口径转成情景或敏感性。
7. 记录采用哪一口径、原因及对模型的影响。

对主论点至少寻找一个最强替代解释。支持与反对证据不必数量相等，但必须按独立性、直接性和代表性加权解释，不能“数票”。

## 7. 校准另类数据与专家信息

流量、信用卡、招聘、下载、卫星、渠道库存、网络测量等另类数据进入Base Case前，至少检验：

- 历史上与公司实际KPI/财务字段的关系、领先/滞后期和稳定性。
- 样本覆盖、面板流失、地域/SKU偏差及方法是否改变。
- 季节性、促销、机器人、重复用户、渠道前置和宏观因素。
- 从信号到收入、利润或现金需要哪些额外假设。
- 信号是否已被市场普遍使用，以及本期是否超出历史噪声。

没有历史校准或方法说明时，只用于方向、情景或Watchlist，不直接写入Base Case点估计。

专家访谈记录角色、任职时间、可观察范围、样本代表性、访谈日期、利益冲突和禁止讨论事项。把“亲历事实、个人解释、对未来预测、行业传闻”分开。单个专家不得代表公司或行业；多个同质专家仍可能只有一个独立证据簇。

## 8. 执行MNPI与数据权利门槛

在获取、保存和使用专家、员工、供应商、客户或泄露材料前执行检查：

1. 信息是否已由发行人、监管文件或可验证公开渠道公开？
2. 是否具体到足以显著改变理性投资者对证券的判断？
3. 来源是否因雇佣、合同、保密、受托或其他义务无权披露？
4. 获取方式是否绕过访问控制、条款、隐私或数据许可？

只要可能同时满足“重大”和“非公开”，立即标记`MNPI_review`并隔离：停止追问细节，不进入模型、报告或投资动作，保留最少必要的合规记录，并按适用组织流程咨询合规/法律人员。不要自行断言某信息绝对不是MNPI；优先用公开来源重新验证命题。

同时记录数据授权、引用限制、个人信息和保留期限。能访问不等于有权用于投资研究或对外发布。

## 9. 决定信息进入哪一层

按证据成熟度和决策用途分流：

- **Base Case**：可公开追溯、口径匹配，且有直接证据或异质独立证据支持。
- **Scenario**：方向可能重要，但样本、口径、独立性或传导仍不足。
- **Watchlist**：动作存在但财务贡献未知，例如招聘、产品发布、许可或标价变化。
- **Quarantine**：可能涉及MNPI、数据权利不清、实体串台或as-of泄漏。
- **Reject**：无法回溯、已被根证据否定、方法失真或不适配命题。

证据升级或降级时记录原因。高材料性冲突未解决前不得进入单点Base Case；低可信但高增量的线索只能触发进一步公开研究。

## 10. 搜索停止规则与质量门槛

维护`search_log`：查询、数据库、筛选条件、日期范围、结果数、有效证据、未覆盖区域和失败原因。满足以下条件后可停止扩展搜索：

- 核心承重命题已有根来源和至少一类异质验证，或明确标记无法验证。
- 连续新增来源只重复现有来源簇，边际上不再改变质量向量或模型。
- 最强反命题已被主动检索并进入thesis/unknown ledger。
- 研究仍未解决的缺口已转成区间、情景、证伪指标或下一验证动作。

交付前拒绝以下做法：

- 用链接数量代替独立证据数量。
- 用“官方/一手”标签代替命题适配和证明边界。
- 把公司口径、专家预测、券商估计或媒体推断写成已核实事实。
- 用没有历史校准的proxy直接预测精确收入。
- 对搜索摘要、AI摘要或二手引用不回溯根文件。
- 忽略信息的观察时间、发布日期和as-of边界。
- 高材料性结论没有反证、来源血缘、模型连接或限制说明。
- 使用可能的MNPI或无权使用的数据支持投资动作。
