# Schedule

只做一件事：整理日程信息，然后向用户指定的一个或多个参会人发送 Outlook 日程邀请。

## 收集信息

需要四项信息：

- 主题；
- 日期和开始时间；
- 地点或线上方式；
- 一个或多个接收日程邀请的参会人邮箱。

参会人必须由用户在本轮输入或从客户端常用参会人快捷项中明确选择。没有参会人时，主动询问“日程邀请发给哪些邮箱？可以填写一个或多个。”不得自动选择或群发本机保存的整个常用参会人列表，也不得从项目库、人脉库或历史待办中推断。

接受逗号、分号、空格或换行分隔的多个邮箱，也接受 `姓名 <email@example.com>`。发送前按邮箱忽略大小写去重并校验格式；任一地址无效时一次性指出需要修正的条目，不发送部分邀请。

其他信息缺失或有歧义时，与邮箱一起一次性问清。未提供结束时间或时长时，默认 1 小时，并在发送前明确说明。优先使用用户明确给出的时区；否则使用 domi 提供的默认时区。

## 发送邀请

1. 先调用 Outlook Calendar `get_profile`，取得当前实际登录账号。该账号的默认日历是事件来源，该账号是日程组织者和邀请发送方；不得把本机保存的账号提示当成真实身份，也不得让用户误以为可以在 domi 内切换发送账号。
2. 将用户信息整理成简洁的主题、精确起止时间、地点和参会人列表。
3. 用户已经明确要求约日程且信息齐全时，用一句话复述发送账号、主题、时间、地点和参会人数后直接执行，不再增加确认步骤。发送账号默认脱敏显示。
4. 使用插件声明的 Outlook Calendar 连接器，在 `get_profile` 返回账号的默认日历创建一个事件，并把全部指定邮箱添加为参会人。创建事件即向所有参会人发送同一份 Outlook 原生日程邀请，不另发普通邮件。
5. 返回创建结果；连接器未确认成功时不得声称已经发送。

## 发送账号检测

当调用方输入首行为 `DOMI_OUTLOOK_PROFILE_CHECK_V1` 时，进入只读检测模式：

1. 只调用 Outlook Calendar `get_profile`，不得读取日程、联系人或资料库，不得创建或修改事件；
2. 最终只输出单行 JSON：`{"email":"当前登录账号的完整邮箱"}`，不得添加 Markdown 或说明；
3. 只有调用方明确声明该结果按私密输出处理、仅保存到本机 Application Support 且不进入任务产物或日志时，才允许在该 JSON 中返回完整邮箱；否则仍须脱敏；
4. 无法取得 profile 时返回真实错误，不得使用本机旧提示或用户输入猜测账号。

## 边界

- 不读取或更新飞书、项目库、人脉库、行业动态、待办事项文档，也不调用其他 domi Skill。
- 默认不检查日历冲突；用户明确要求时才检查。
- 不自行实现 OAuth、SMTP、ICS 邮件或 Microsoft Graph 凭据。
- 不把私人邮箱写入仓库、文档、普通输出文件或日志；除上述私密发送账号检测模式外，结果中只脱敏显示。
- 默认同一事件中的参会人可能互相看到邮箱；用户明确要求隐藏收件人时，先说明需要分别创建邀请并等待确认。
- Outlook Calendar 未连接时，直接提示用户完成连接。
- 用户只要求整理文案而未要求创建或发送时，不写入日历。

## 输出

简洁返回：脱敏后的实际发送账号、主题、时间、地点、参会人数、各脱敏邮箱的邀请状态，以及“已发送”或具体失败原因。
