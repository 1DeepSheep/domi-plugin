# 完整执行示例

仅在需要核对阶段顺序、编写测试或仍不确定交付形态时读取。规范性要求以入口 Skill 和其他已路由 reference 为准。

## 完整示例

**User**：帮我用 asr-notes 处理这个文件：20260115-星辰科技-会议录音.txt

**Agent 执行流程**：
1. 确认使用默认话题板块（团队背景 / 产品与技术 / 商业化 / 市场与行业 / 融资情况 / 其他）
2. 读取源文件
3. 扫描实体 → 识别关键数字并交叉验证 → 搜索验证 → 构建纠错映射；项目访谈中同步建立核心成员学历证据表、履历时间线和模型工作表
4. 逐段精修（内部过程，乱码段落标记存疑，不静默跳过）
5. 确定笔记标题（根据内容：`20260115-星辰科技（StarTech）-具身智能`）
6. 按板块归类重组，应用各板块专属规则和内容过滤规则 → 输出 `20260115-星辰科技（StarTech）-具身智能.md` 初稿
7. 执行完整性审计：对照必查清单逐项核对，补充遗漏、标记待确认项
8. （如有辅助材料）执行材料校验
9. 执行待确认项联网复核：扫描笔记中所有 ⚠️ 标记，逐一联网搜索验证，消解疑点，仅保留影响判断的最短未决边界
10. 对最终正文重新执行学历证据表、履历时间线、模型工作覆盖、跨层级串线和归因一致性检查；任何改动后的确定语气事实都必须重新绑定证据
11. 告知用户笔记已生成

> 注：第 4 步的逐段精修仍然是必要的内部过程（为第 6 步归类提供干净的文本），只是默认不输出精修稿文件。用户明确要求逐字稿时才额外输出 `20260115-星辰科技（StarTech）-具身智能-refined.md`。

**Agent 最终告知用户**：
> 已生成纪要：`20260115-星辰科技（StarTech）-具身智能.md`。
