# 创始人履历格式规范

模式A中，创始人履历必须让读者快速看清“何时在哪里、做什么、形成了什么能力”。不要把履历写成证据审计报告，也不要用一个笼统的“工作经历”父bullet包住全部经历。

## 一、固定结构

按以下顺序组织；没有内容的项目直接省略：

```markdown
**姓名（英文名，当前职位）**

- 本科：YYYY-YYYY年，学校，院系／专业
  - 在校创业或其他直接影响能力判断的经历
- YYYY-YYYY年，公司，部门／岗位
- YYYY-YYYY年，公司，部门／岗位
- YYYY-YYYY年，公司，岗位
  - 方法、模型、参数、指标、组织责任或产品结果
  - 同一时期的第二项高信号事实
- 创业动因：...
- 行业研究：...
```

- 学历直接按层级写`本科／硕士／博士`，不要再加“学历：”父bullet。
- 每段工作经历单独作为一级bullet，按时间从早到晚；不要再加“工作经历：”父bullet。
- 同一段经历的职责、技术方法、关键参数、结果和反思放在二级bullet；不得把跨公司的事实塞进同一条。
- 年份区间统一写`YYYY-YYYY年`；只有材料精确到月份时才写`YYYY年M月-YYYY年M月`；当前经历写`YYYY年至今`。
- 来源链接放在所支持事实的句末括号内，不另起“公开资料显示／未独立核验／本纪要不采用”的过程句。

## 二、出生年份推算

- 有直接来源时写直接年份。
- 没有直接出生年份、但本科首次入学年份明确时，允许按`本科入学年份-18`推算；正文表格写`YYYY（推算）`，内部来源账本记录公式，例如`<本科入学年份>-18=<推算出生年份>`。
- 推算值只用于履历汇总表，不得改写成“出生于YYYY年”或作为年龄精确计算依据；若存在明确的跳级、延迟入学或其他反证，则优先采用反证并说明最短必要边界。

## 三、履历汇总表

详细bullet之后固定使用五列：

```markdown
| 姓名 | 出生年份 | 当前职位 | 学历 | 工作经历 |
|---|---|---|---|---|
| 姓名 | YYYY（推算） | 当前职位 | 本科：YYYY-YYYY年，学校，院系／专业 | YYYY-YYYY年，公司，部门／岗位 <br />YYYY-YYYY年，公司，部门／岗位 |
```

- 表格只做快速检索，不重复方法、参数、指标和长篇项目细节。
- 单元格内换行统一用原始内联 HTML token ` <br />`；不用`<br>`、分号或箭头代替，也不得写成反斜杠转义、反引号代码或 HTML 实体，否则客户端会把它显示成字面文本而不是换行。
- 汇总表不得重新概括履历。逐人从上方已核验的学历和工作经历bullet按原顺序投影：一条bullet对应单元格中的一行，多条内容用` <br />`连接；不得用空格、逗号或顿号把两段经历连成一段。
- 保存前逐行核对：学历或工作经历有`N`段时，单元格必须保留`N`段文本和`N-1`个`<br />`。计数不一致即为格式审计失败，必须先重建该单元格，不能交付或归档。
- 表格字段与上方bullet必须完全一致；名称或时间修正时两处同步更新。

## 四、排版细节

- 加粗人名行前后各留一个空行；同一人物的连续bullet之间不留空行。
- 一级bullet使用`- `；二级bullet固定缩进两个空格后使用`- `。
- 中文与数字、英文之间不加空格；英文品牌和缩写采用官方大小写，例如`TikTok`、`PDF`。
- 一个bullet只承担一个主结论；需要解释“如何做到”的内容下沉为二级bullet。
- 纪要正文不出现搜索路径、候选排除、缺失字段枚举、反复核验说明或“为什么没写”的解释。

## 五、交付检查

- 是否一眼能读出创始人的时间线，而不是先读一段来源说明？
- 每段关键经历是否保留了能证明能力的具体方法、参数或结果？
- 是否删除了没有信息增量的审计过程句？
- 出生年份若为推算，是否明确写`（推算）`且只出现在汇总表？
- 五列表格、` <br />`换行、缩进和品牌大小写是否一致？
- 汇总表每一段学历／工作经历是否各占一行，且没有被空格、逗号或顿号连写？
