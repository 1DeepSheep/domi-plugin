# 检索、证据、去重与评分

## 检索矩阵

每次扫描同时覆盖：

1. 用户领域原词、现有 taxonomy 名称、英文名、缩写和常见别名。
2. `融资 / funding / round / investment / valuation / acquisition / IPO`。
3. `发布 / launch / product / model / customer / partnership / order / revenue`。
4. `基金 / fund close / investment thesis / partner / joined / left / portfolio`。
5. `政策 / regulation / guidance / approval / standard / supply / demand / price`。

中国项目追加公司官网、公众号可检索线索、DeepTech 深科技、36Kr、晚点、甲子光年、量子位、投中、融中及行业垂媒；全球项目追加监管披露、公司和机构官网、主流创投媒体与相关技术社区。技术型赛道检查 GitHub、Hugging Face、论文、产品 changelog 和招聘等可观察动作。

每轮快速扫描固定追加一组专业媒体论点信号词：

```text
DeepTech 深科技 / 对话 / 访谈 / 专访 / 公开观点 / 趋势判断 /
roadmap / outlook / interview / prediction
```

此组用于发现技术能力边界、明确时间表、工作流重构、产业竞争格局和商业化判断。它不是按人物逐一搜索，也不能把泛泛观点自动提升为事件。

## 分类归一与新子领域判断

以本地 SQLite taxonomy 与 `investment-mgmt/references/taxonomy.md` 为 canonical 词表、父子关系和别名表：

1. 先做 exact 与 alias 匹配。
2. 再判断能否由现有多个子领域组合表达；能组合时不得新建。
3. 新闻表已有但项目表没有的选项是 orphan，不得使用或反向提升。
4. 只有同时满足以下条件才输出 `taxonomy_request(kind=new_subdomain)`：唯一归属现有一级领域；与名称和别名不重复；不是产品、功能、模型版本、事件或短期热点；粒度与同级相当；至少覆盖两个独立商业主体及两个独立可靠来源，或有监管／标准组织正式定义。
5. 单次扫描最多提出两个自动创建候选；其余标为 `deferred`。

分类判断与新闻可信度评分分开。某个事件证据充分，不代表其新闻用语自动构成一个稳定新赛道。

## 来源与证据优先级

```text
监管／交易所／政府正式文件
> 公司或机构官方披露、论文与产品原始页面
> 高质量独立专业媒体
> 专业数据库
> 聚合转载和社交线索
```

- 一手来源适合确认“谁在何时声称了什么”，不自动等于独立核实。
- 多家媒体引用同一通稿仍只算一个来源链。
- 数据库用于发现，融资金额、轮次、投资方等应尽量回溯最上游来源。
- 原创专业媒体访谈可用于确认“受访者在何时公开表达了什么判断”。如没有独立材料验证判断本身，通常标为“二手报道”；若能直接打开受访者或机构发布的完整原文，可按“公司／机构口径”处理。不得把预测改写成已经发生的事实。

Base 的证据状态固定映射：

| 状态 | 使用条件 |
|---|---|
| 独立核实 | 监管披露、审计信息或真正独立证据确认 |
| 公司／机构口径 | 公司、创始人、投资机构或其通稿声称 |
| 可观察动作 | 产品、招聘、代码、定价、上架等动作确实存在 |
| 二手报道 | 专业媒体或数据库报道，但未回溯到足够一手证据 |
| 传闻／待核验 | 社交线索、匿名信源、事实冲突或关键信息无法确认 |

## 事件级去重

- URL 规范化：去掉 `utm_*`、`from`、`spm`、fragment 和会话参数，尽量解析真实跳转链接。
- 同一原始链接或同一通稿的转载不能重复写入，也不能因转载量提高可信度。
- 用“核心实体 + 信息类型 + 时间窗口 + 关键事实”判断是否同一真实事件。
- 传闻后出现正式官宣，使用同一不可变事件键定位并更新原事件；保留既有事件 ID，不要创建第二条。
- 金额、估值、投资方、客户或政策解释出现实质增量时更新原事件并重算评分。
- 两个事件高度相似但无法可靠判断时，跳过自动合并与写入，列入 `skipped` 待人工判断。
- 深度访谈／公开观点使用 `人物或机构 + 规范化核心论点簇 + 公开观点披露` 作为不可变事件语义；媒体名、标题措辞和发布日期不进入事件键。相同人物在不同时间重复同一论点且没有实质增量时合并；时间表、能力边界或商业化判断发生实质变化时可视为新事件，但必须做语义比对。

## 深度访谈与投资论点信号采纳门槛

专业媒体的对话、访谈、专访、演讲或公开观点可以作为 `行业趋势` 采纳，但必须同时满足：

1. 说话者身份可由姓名加组织、角色、项目或 canonical profile 唯一确认。
2. 存在可访问原文，且发布时间、发布主体和原话语境可核验。
3. 至少包含一项具体、可证伪、会影响产业或投资判断的主张，例如技术能力边界、明确时间表、成本/效率量级、竞争格局、商业化路径或工作流范式变化。
4. 摘要明确使用“某人判断／预计／认为”等归因表达；把已发生事实、受访者判断和雷达投资含义分开。
5. 不是泛泛愿景、个人鸡汤、无新增信息的转载摘要或标题党。

命中 A/S 重点人物可提高相关性与提醒优先级，但不能替代以上门槛，也不能提高来源可信度。

## 重要性 1–10

从五项各取 0–2 分并求和：

1. 与指定领域、本地重点项目或既有投资主题的相关性。
2. 是否代表技术、需求、政策或成本拐点。
3. 是否包含融资、商业化、客户、收入或产品采用信号。
4. 是否会改变竞争格局、资本流向或关键公司的位置。
5. 事件规模、时效性、新颖度和可行动性。

等级映射：

| 分数 | 等级 | 默认动作 |
|---:|---|---|
| 10 | P0-立即关注 | 立即关注 |
| 8–9 | P1-重点关注 | 进入深研或继续跟踪 |
| 5–7 | P2-日常跟踪 | 继续跟踪 |
| 1–4 | P3-仅归档 | 仅归档 |

## 重点项目／人脉匹配与提醒

`priority_watch` 的项目侧只包含评级 A 及以上且状态为“深度跟踪”的对象；人物侧包含评级 A 及以上对象，关系进展只作背景与消歧，不作为准入条件。项目侧来自 `priority-watchlist.md`，A 及以上固定为 `A / S`；人脉表按运行时 schema 中明确高于或等于 A 的选项解释。匹配规则：

1. 项目直接匹配需命中规范公司／项目名、可靠别名、产品或已确认创始人，并与新闻主体一致。
2. 人物直接匹配需在姓名之外再由当前／历史组织、角色、项目、canonical profile 或其他强身份信号完成消歧。
3. 新闻只涉及竞品、同赛道政策或泛行业趋势时属于 `related`，不是 `direct`；按普通关注阈值返回，不能借重点对象提高优先级。
4. 重点对象身份只能提高“与本地重点项目或既有投资主题相关性”这一项，通常取 2 分；不得改变来源可信度，也不得让无事实或无具体论点增量的内容进入 accepted events。

提醒级别：

- `立即提醒`：可能改变投资判断或需要近期动作，例如新融资／估值跳升、重大客户或订单、并购、创始人或核心高管变化、监管诉讼、严重负面、明确募资或创业动作。
- `重点更新`：产品、模型、论文、开源、合作、招聘等有明确事实增量，但暂不要求立即动作。
- `仅归档`：泛泛提及、转载、榜单、常规招聘或缺乏增量的信息。

`direct` 且属于实质事件、可信度 >= 6 的事件进入 `priority_alerts`，即使重要性低于一般回传阈值 7；可信度不足时仍按既有“传闻／待核验”规则处理，不得把未经核验的信息作为事实主动提醒。

## 可信度 1–10

从以下维度综合判断：来源权威性 0–4、一手证据 0–2、独立交叉验证 0–2、实体／时间／事实一致性 0–2。明显冲突应扣分，未解决冲突最高不超过 5。

参考：

- 9–10：监管或官方明确披露，且关键事实一致；或有强独立验证。
- 7–8：可靠的一手公司／机构口径，或多个独立专业来源一致。
- 5–6：单一可靠媒体或数据库，信息仍不完整。
- 1–4：传闻、匿名信源、二手转引或存在明显冲突。

## 是否值得关注

默认：

```text
重要性 >= 7 且可信度 >= 6
```

重要性 >= 9 但可信度 < 6 的事件，不勾选「是否值得关注」，保留在事件库供后续核验，默认不向用户回传。评分必须附 1–2 句理由；不要仅输出数字。
