# Desk Research / 投研桌面研究

把零散的检索变成可复用、可追溯、可落库的投资研究成果。本 skill 是**编排器**：它定义研究框架和质量标准，调用已有能力（搜索、金融数据、内部知识库、飞书）完成工作，最终产出落到飞书文档或多维表格。

## Codex 运行说明

在 Codex 中执行时，用当前可用的联网、浏览器、金融数据和 lark-* / lark-cli 能力替代旧 Claude 工具名；任何最新新闻、上市公司数据、融资动态、法律/政策变化都必须联网核验并标注来源日期。飞书写操作遵循对应 lark skill 的权限和确认规则。

## 两类交付物（mode）

| Mode | 交付物 | 何时用 |
|---|---|---|
| **company** | 公司/标的深度画像 | 锁定单一公司/项目/股票，要全面摸清 |
| **sector** | 行业/赛道扫描 | 锁定一个行业/主题，要梳理格局与机会 |

一次请求可只做其一，也可「先 sector 扫描定位，再对入围标的做 company 画像」。

## 统一框架 + 市场分支

研究骨架（5 步流程）对一级、二级通用；**信息源、估值口径、退出逻辑、可得性**按市场分支。开工前先定位 `market`：

- **一级（primary / VC·PE）**：未上市项目。重团队/产品/融资/市场空间/竞品，数据稀疏、多靠一手信源与推断，需标注置信度。
- **二级（secondary / 公开股票）**：上市公司。重财报/可比公司/催化剂/估值，数据密集、可量化，偏好结构化金融数据源。
- **拿不准**：默认按标的属性推断并在第 0 步一句话和用户确认。

## 标准流程（5 步）

### 第 0 步：锁定范围与路由（务必先做）

产出一行「研究配置」并与用户确认（信息充分时可直接开工）：

1. **mode**：company / sector（或两者串联）。
2. **market**：primary / secondary。
3. **标的指纹**（company mode 必做）：固定拆成「官网域名｜运营/法律实体｜品牌｜产品｜前身/兄弟产品｜各自当前状态｜一句话业务」。**这一步防错最关键**——务必把后续所有事实（创始人、融资、营收、股票代码）绑定到「这一个」实体，区分同名公司、母子公司、关联方，以及“改名/关闭/仍独立运营”等不同状态。二级再补：交易所 + 股票代码。
4. **depth**：quick（聚焦用户点名的维度，但仍完成实体、口径和来源校验）/ standard（标准画像）/ deep（深度，多轮+对抗校验）。
5. **范围边界**：时间窗、地域、是否含竞品对比、是否复用内部已有材料。
6. **多标的横评**：用户同时给出 2-5 个公司时，仍走 company mode，但先为每个标的分别锁定指纹，再统一比较维度、指标定义和截至时间；不得把不可比口径硬放进同一排名。

> 一句话确认示例：「按【二级 / company / 深度】研究 PDD（拼多多, NASDAQ:PDD, 运营主体 PDD Holdings），含中概电商可比公司对比，产出落飞书文档。对吗？」

### 第 1 步：选框架

按 mode 读对应 reference，按 market 选其中的分支维度：

- **company mode** → 读 [references/company-profile.md](references/company-profile.md)
- **sector mode** → 读 [references/sector-scan.md](references/sector-scan.md)

把框架维度展开成一份「待填问题清单」，作为第 2-3 步的填空目标。

### 第 2 步：取数（按源路由）

按 market 和维度选信息源，**优先专业/内部源，公开搜索补全与交叉验证**。完整路由表与调用方式见 [references/sources-and-output.md](references/sources-and-output.md)。速记：

- 公开网络 → `web-search` / `news-search` skill（Brave）；深度多源编排用 `deep-research`。
- 二级金融数据 → `daloopa:*`（财报/建模/可比/DCF/tearsheet）、`bigdata-com:*`（company-brief / sector-analysis / peer-comparables / valuation-snapshot / risk-assessment / variant-perception）。
- 一级项目深挖 → `product-deep-research` skill（团队/商业模式/增长/竞品 8 模块）。
- 内部知识库 → `investment-mgmt`（Watching List/Wiki/本地资料库）、`lark-wiki`、`lark-base`、`feishu-doc-reader`。**开工前先查内部是否已有该标的/赛道的材料，避免重复劳动。**若当前环境没有相应连接或权限，明确标注“内部资料未覆盖”后继续公开源研究，不把连接缺失误报为标的没有内部记录。
- **一级项目创始人双语检索（standard/deep 必跑；quick 涉及团队、起源或转型判断时跑）**：对每位创始人同时检索中英文名/常用账号 × `访谈|专访|播客|演讲|融资|创业`，并加公司中文名/英文名；中国项目再定向查甲子光年、36Kr、晚点、Founder Park、暗涌、微信公众号等。standard/deep 即使官网、GitHub、论文已足够成稿，也不得跳过。原站漏索引时查标题精确匹配、转载页和公众号镜像。
- **一级公司考古与商业动作检索（standard/deep 必跑，quick 按问题聚焦）**：追溯运营主体、旧域名、前身/兄弟产品、历次 pivot、融资与产品发布，建立统一时间线；再检查定价页、产品文档、集成目录、Marketplace、Creator/Affiliate/Referral Program、客户案例、评价平台、招聘与内容索引。目标是找出真正改变产品和增长轨迹的动作，而非只收集公司简介。
- 技术/研究型标的产出全集（standard/deep 必做）→ **GitHub org + HuggingFace org**（带 star/下载/日期，一次拿齐产出清单+采用度+迭代节奏）；标的官网是 SPA 时用浏览器/CDP 渲染**索引页**（blog/news/benchmarks）枚举其工作，别只信静态抓取首页。quick 只取与用户问题直接相关的仓库/模型及采用度代理，并明确 stars、forks、下载量不等于客户或收入。
- 中文/另类数据源（公众号、雪球、天眼查、巨潮、券商研报、小红书、**招聘页=投资方/战略线索**等）与各平台的**访问壁垒绕法**、检索算子 → 见 reference 第 2-4 节。公众号正文须走「搜狗微信→解析真实链接→CDP 抓正文」（reference §3 SOP），`site:` 直抓拿不到。

每条关键事实记录来源与日期；推断标注「（推测）」并与已证实事实区分。委派子任务时未核实指标标「（待验证）」，避免错数字被层层锚定。

### 第 3 步：结构化分析

把取到的数据填入框架，并完成 mode 对应的分析动作（详见 reference）。无论哪种 mode，都要收敛出：

- **3-5 条核心发现**（带支撑数据）。
- **多空/利弊两面**（bull vs bear / 看好理由 vs 风险点）。
- **关键假设与待验证项**（投资逻辑成立的前提是什么、还缺什么数据）。
- **结论与下一步**（继续深入 / 安排访谈 / 放弃 / 进入估值或 IC 流程）。

**长访谈抽取门槛（一级 standard/deep 必做；quick 仅抽取与问题直接相关的段落）**：找到创始人长访谈后，不得只把它当背景材料。逐项抽取并标记：①完整教育/任职/论文与创业履历；②公司起源与实体关系；③产品与技术机制；④量化进展及时间点；⑤客户、定价、收入、盈利、融资；⑥成本结构和商业模式；⑦创始人对市场规模/采购预算的口径；⑧战略变化、竞争判断；⑨可核验线索。每项注明「创始人口径/媒体核实/独立核实」。

**公司考古与关键转折（一级 standard/deep 必做）**：把「法律实体/品牌/产品版本/前身与兄弟产品」「融资」「产品发布与 pivot」「客户/收入/安装量节点」「渠道或定价变化」放到同一条时间线上。每个转折都回答：发生了什么、为什么改变、结果证据是什么、是否真正带来 PMF。模型、功能版本和独立产品不得混为一谈；集团融资与单一产品融资必须分开。

**Founder–Product Fit（一级 standard/deep 必做）**：从长访谈和创始人原文中只保留 2-4 条真正影响产品决策的原则，按「原话 → 对应产品/商业动作 → 结果或代价 → 真信仰还是融资叙事」展开。没有动作支撑的口号只作背景，不进入核心发现。

**客户—任务—付费工作流（一级 standard/deep 必做）**：用 3-5 个有来源的真实工作流说明使用者、决策者、付款者、原流程、Aha moment、替代的是人/软件/外包、持续付费原因与流失风险。没有代表性样本时按证据频率排序，不得编造用户画像占比。

**从事实到 thesis**：对关键事实同时回答“所以呢”。不要满足于“报告里提到过”。将事实按决策重要性分为：A. 改变投资判断（置于摘要）；B. 支撑核心逻辑（进入正文主线）；C. 背景信息。若一手访谈披露了客户、定价、盈利、产量、性能或关键 Pipeline，必须进入摘要和核心发现，不能埋在团队介绍或技术清单中。

**机制化分析链**：核心结论统一写成「事实 → 可能机制 → 投资含义 → 反证/替代解释」。若只有动作存在（如上线 Creator Program、进入 Marketplace），没有渠道归因、用户调查、UTM、转化或 cohort 数据，只能写“与该增长假设一致”，不得写“真正驱动/主要靠/导致”。增长动作还必须早于被解释的结果，否则不能建立因果。

**关键数字台账（company mode 必做）**：融资、估值、收入、ARR/RR、客户、用户、安装量、团队、定价等进入一张 Claim Ledger，至少记录「指标｜原始披露术语｜数值｜实体范围｜定义/分母｜截至时间｜最上游来源｜证据状态｜置信度」。报告中的重复数字只能引用该台账；不得把 `revenue run-rate` 自动改写为 ARR。存在冲突时先解决；解决不了就并列保留时点与口径，累计融资等只报可核验下限、区间或 unresolved，不强选单点。

> **技术/研究型标的：先盘产出，再下定性。** 产出的「形状」本身就是 thesis——把每个发布/模型/repo/benchmark 带日期列全（GitHub/HF/官网索引页），看清是横向复制同一套方法论还是真发散，再收敛判断。**跳过盘点直接定性极易翻车**（如把"系统性铺赛道"误判成"方向发散"）。

> **信号三角验证**（形成动能假设、识别叙事注水）：把多个可观察信号交叉读，而非单点引用；这些信号只支持假设，不替代收入质量、付费转化、留存、毛利等经营验证。
> - 一级常用信号：招聘扩张（脉脉/BOSS/LinkedIn 岗位数）× 融资节奏 × 产品迭代频率 × 搜索/社媒热度。
> - 二级常用信号：业绩指引 × 机构持仓/北向 × 产业链上下游景气 × 研报一致预期 vs 自己判断。
>
> | 招聘 | 融资 | 产品迭代 | 搜索/社媒 | 支持的假设（仍需经营数据验证） |
> |---|---|---|---|---|
> | ↑ | ↑ | ↑ | ↑ | 动能可能较强，多信号共振 |
> | → | ↑ | → | ↑ | 融资与传播领先于产品行动，需警惕叙事注水 |
> | ↑ | → | ↑ | → | 产品投入较强，市场认知或商业转化尚待验证 |
> | ↓/→ | → | ↓/→ | ↓ | 动能可能减弱，需排除成熟期、季节性或隐性增长 |
>
> 先指出标的落在哪种组合，再写它对增长质量的含义。各信号的具体取法见 [references/sources-and-output.md](references/sources-and-output.md)。

### 第 4 步：对抗校验（standard/deep 必做，quick 可略）

下结论前自我证伪，重点查这几类常见错误：

- **实体张冠李戴**：营收/融资/创始人是否真属于这一个标的（同名、母子公司、关联方）。**警惕大同名实体**：若存在著名同名公司（如 UniPat↔UiPath），定量搜索（融资/财务）整列可能被污染，且「搜不到」≠「没有」，需换名/换源再确认。
- **数字与时点**：财报口径、币种、单位、是否最新；融资轮次与金额是否一手来源。
- **关键指标一致性**：逐项核对 Claim Ledger，禁止混用 ARR 与 annualized revenue run-rate、累计与新增、organization/team/workspace/注册/活跃/付费客户、总员工与工程团队；产品、公司和集团口径分别列示。
- **来源质量**：核心数字是否仅靠搜索结果共现、PR 稿、单一信源。**多源 ≠ 交叉验证**——若几家媒体同回溯到一篇 PR 通稿/同一转载源，仍是公司口径，需找真正独立的源。
- **自建榜单归属**：标的自办的 benchmark/leaderboard，要分清「谁的榜」与「谁登顶」——榜首常是第三方大模型而非标的自家模型，勿误记为其战绩。
- **叙事 vs 行动**：增长引擎、护城河是否被公司自述带偏，是否有可观察证据支撑（用第 3 步「信号三角验证」表交叉佐证）。
- **动作 vs 贡献**：确认增长动作是否早于增长结果，是否有归因证据；“计划存在”“投资人有影响力”“上架平台”都不能自动推出收入或获客贡献，也不得由投资关系推断平台审核优待。
- **覆盖率假象**：最终审计不能只问“是否提到”，还要问“是否保留完整限定、是否放在正确层级、是否解释了投资含义”。对长访谈逐项回查抽取表；A类事实若只在后文出现或被一句概括，视为漏项。

发现存疑就回到第 2 步补数或在成果中明确标注不确定性，不要硬下结论。

### 第 5 步：落库（飞书）

按用户偏好把成果写入飞书，方法见 [references/sources-and-output.md](references/sources-and-output.md)：

- **飞书文档**（默认，长文画像/扫描报告）→ `lark-doc`：由 Markdown 创建文档。
- **多维表格**（结构化/可对比/入管道）→ `lark-base`：写入记录；若是在管理 deal flow，优先走 `investment-mgmt` 的 Watching List。
- 落库后回链：把文档链接回填到内部知识库相应位置（Wiki / Watching List），保持三系统一致。

## 质量基线

- **来源纪律**：核心数字必带来源与日期；区分「已证实 / 推测 / 缺失」。
- **可追溯**：成果保留信源清单，方便复查与更新。
- **证据状态**：关键结论区分「独立核实 / 公司口径 / 可观察动作 / 推算 / 假设 / 缺失」；一手来源描述谁说了什么，不等于事实已被独立验证。
- **可证优先于填满**：公开证据不足时减少画像、工作流、竞品或增长机制数量，不为满足模板强行补齐；禁止无样本的用户占比、无底层数据的收入结构占比和伪精确 TAM/ACV。
- **两面性**：永远同时给出看好与风险，不做单边鼓吹；不提供个性化投资建议（涉及买卖决策时只做事实与逻辑梳理）。
- **中文一级项目最低检索集**：创始人中英文名、公司中英文名、核心产品名分别与「访谈/专访/播客/演讲/融资/客户/收入」组合检索；未执行不得宣称完成 standard/deep 画像。
- **市场口径**：一级标注数据稀疏与置信度；二级注意财报口径、币种、可比口径一致。
- **不重复造轮子**：能力已存在就调用（搜索/金融数据/飞书/深度研究），本 skill 只负责框架、路由、质量与落库。
