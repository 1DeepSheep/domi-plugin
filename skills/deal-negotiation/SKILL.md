# 投资交易谈判指导

根据用户描述的谈判场景，提供针对性的沟通话术和条款策略建议。

## Codex 运行说明

本 skill 已按 Codex 原生目录组织。读取 reference 时使用当前 skill 目录下的相对路径；不要读取 `.claude` 目录或 `.skill` 压缩包。每次输出前确认已按场景读取 `references/philosophy.md` 和至少一个场景文件。

## 工作流程

1. **明确场景** — 确认投资阶段（天使/种子/A/B/C+/Pre-IPO）、谈判环节（首次接触/尽调/估值/条款/签约）、当前态势（竞争性/独家/困境）
2. **加载参考资料** — 根据场景读取对应的 reference 文件
3. **输出建议** — 根据具体情况给出话术建议和/或条款策略

## 参考资料

根据用户需求读取对应文件。**每次谈判分析前必须先读 philosophy.md 确认优先级框架。**

- **核心理念**：[references/philosophy.md](references/philosophy.md) — **必读**。基金交易谈判的底层逻辑：份额>估值、经济权益>控制权、条款优先级分层、MFN 保底策略、创始人限制的逻辑、共赢导向
- **沟通话术**：[references/communication.md](references/communication.md) — 首次接触、尽调沟通、估值讨论、僵局处理、关系维护、拒绝话术
- **条款谈判**：[references/term-sheet.md](references/term-sheet.md) — 估值方法、清算优先权、反稀释、董事会治理、创始人锁定、退出条款、按阶段的条款重点
- **场景应对**：[references/scenarios.md](references/scenarios.md) — 创始人常见异议、竞争性交易、困难场景（down round/团队问题/对赌）、特殊交易结构（可转债/分阶段投资/老股转让）
- **天使轮模板**：[references/angel-template.md](references/angel-template.md) — 基于实际签署的开曼红筹天使轮文件（TS/SPA/SHA）提取的完整条款结构、金额参数、谈判要点注释（单一领投场景）
- **Pre-A 多机构模板**：[references/preA-template.md](references/preA-template.md) — 基于实际签署的开曼红筹 Pre-A 文件（SPA/SHA）提取，多家机构联合投资场景：Requisite Preferred Holder/Majority 共同权利机制、8% 持股门槛体系、super pro-rata、创始人加权投票控盘、分层 veto、Token 发行等新经济条款。含与天使轮的逐项差异对比
- **SAFE 模板（美元 Post-Money）**：[references/safe-template.md](references/safe-template.md) — 基于实际签署的美元 SAFE 文件提取，底稿为 YC Post-Money SAFE（Valuation Cap 版 v1.2）但加入多处非标准投资人保护。覆盖浮动 Cap、合格 vs 非合格融资分层转股（110% / 20% 折扣）、18 个月兜底、尽调整改权、MFN、信息权，含与标准 YC SAFE 的逐项差异对比。适用美元早期/战略投资、暂不定价快速打款的场景
- **案例对比**：[references/case-comparison.md](references/case-comparison.md) — 不同机构天使轮 TS 风格横向对比，提炼可借鉴做法与本基金相对优势

## 匿名化规则（强制）

**输出中绝不出现真实项目名、机构名、创始人姓名。** 参考文件内的案例数据已统一用代号脱敏，对外产出时一律沿用代号，必要时新建代号指代：

- **本基金** = 我方
- **机构A / 机构B / 机构C …** = 其他外部投资机构
- **项目M / 项目J …** = 具体被投项目
- **创始人** = 任何创始人/核心团队成员

若用户在对话中提供了真实名称，理解即可，但写入任何文档、TS、分析时都要替换为代号。

## 输出原则

- 话术建议用引用块（blockquote）格式，方便直接参考
- 条款分析用表格对比利弊
- 每个建议标注适用场景和注意事项
- 根据对方的经验水平调整话术风格：新手创始人侧重解释教育，老手创始人侧重效率和直接
- 始终平衡投资人利益保护与创始人关系维护

## 交易文件条款总结格式（首选）

当用户要求**总结/梳理某份交易文件的关键条款**（TS / SPA / SHA / SAFE 等）时，默认用以下"逐条 + 核心含义"格式：

- 编号 + **加粗条款名 + 冒号**，例如 `1. **保护性条款：**`、`2. **回购权：**`、`3. **优先清算权：**`
- 每条下用 1–N 个子弹点说明**该条款的核心含义**——是什么、起什么作用、怎么运作；**不要照搬法律全文，也不要逐个投资人罗列细节**
- **把握颗粒度**：读者要的是"这条是什么意思、有什么效果"，不是精确数字或具体哪家机构持有多少。要泛化表述："主要投资人""特定投资人""竞争对手清单"，不要写"本轮投后包括机构B、机构C、战投S……"
- **身份与数字脱敏**（遵循下方匿名化规则）：当事方 → 代号（[本基金]、[创始人甲]、[机构A]、[战投S]…）；金额/估值/单价/份额/股数 → 占位符（[金额]、[估值]、[单价]、[比例]、[股数]、[门槛金额]、[出售估值门槛]）；保留不具识别性的通用法律/机制参数（如 50%/100%、1/48、180 天、ESOP 单人 10% 上限）
- 排版从简：加粗条款名 + 子弹点，不要大表格或多层嵌套
- 若用户要的是更完整的画像（而非单纯压缩一份文件）：覆盖各类核心条款，明确标注**缺失**的常见条款（如"无 MFN"），体现双方公司架构，并以"核心内容总结"收尾给出整体判断（投资人友好 / 加强下行保护 等）

> 该格式由用户在「极群/GroupUltra 交易文件条款总结」任务中确认。生成 Word/对外文件时一律按上述规则脱敏，绝不出现真实项目名、机构名、创始人姓名及具体金额。
