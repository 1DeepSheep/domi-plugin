## domi 的价值

通用 AI 可以回答问题，domi 更关注一项投资工作是否真正完成。它为 Codex 提供 15 个相互协作的投资 Skills 和严格的工作流路由，让研究、判断、资料管理与后续动作可以在同一个任务中连续执行。

```text
录音 / 文档 / 网页 / 项目线索
            ↓
转写与结构化 → 研究与投资判断 → 本地归档 → 持续跟踪 → 飞书发布 / 日程动作
```

### 1. 不只生成内容，而是完成端到端工作

- 一段项目交流录音可以依次完成：本机录音、PLAUD 文字稿、结构化纪要、核心观点、投资快评、跟进事项和资料入库。
- 一个公司名、链接、BP、截图或项目材料可以依次完成：桌面研究、事实核验、投资评级、项目文档和结构化记录。
- 一次行业扫描可以依次完成：多源检索、原文核验、实体归一、事件去重、重要性与可信度评分、重点对象匹配和事件入库。
- 对受 Router 管理且产生阶段回执的多阶段流程，已完成产物和状态会被保留，并可从已确认的安全点恢复，降低重复生成、重复建档或重复外发的风险。

### 2. 给出投资判断，而不只是摘要

domi 的工作流围绕投资决策设计，可以处理项目快评、B/A/S 评级、IC 投委会材料、招股书与财务报表分析、Datapack／BP 分析、交易条款梳理和投行／咨询风格研究报告。关键事实与投资判断分开表达，重要结论要求来源、时间和待验证项。

### 3. 把零散信息变成可积累的机构记忆

项目、人脉、行业事件、研究文档、会议纪要和待办事项进入同一套本地主库。domi 可以在用户授权的数据范围内跨资料检索、去重和关联，让后续研究不必从零开始，并能从重点项目、人物和关键日期中整理下一步行动。

### 4. 帮助投资人扩大信息覆盖面

domi 可以 mapping 赛道项目与潜在创始人，沿项目页、论文、开源仓库、团队和关系线索做系统化覆盖，降低检索盲区；也可以在每次用户发起的行业雷达扫描中追踪新闻、融资、政策、技术、公司和机构动态，优先提示可能改变现有判断的事件。

## 核心能力

| 能力 | domi 可以完成的工作 |
| --- | --- |
| 录音与会议纪要 | Mac 本机录音、PLAUD 转写、ASR 精修、说话人结构、完整纪要、核心结论与跟进事项 |
| 项目研究与入库 | 从公司名、链接、BP、截图或材料开始，完成桌面研究、查重、评级、项目文档、结构化记录和附件归档 |
| 投资判断 | 3–5 条高密度快评、1–10 分评分、B/A/S 评级、风险与关键验证问题 |
| 深度分析 | 招股书、年报／季报、财务报表、Datapack、BP、商业模式、运营与财务质量分析；可制作 slides 或 HTML／PDF 研究报告 |
| IC 与交易 | IC 投委会决策报告、Term Sheet／SAFE／SPA／SHA 条款梳理和交易谈判准备 |
| 行业雷达 | 新闻、RSS、重点公众号与公开播客信源；原文核验、事件级去重、评分、重点项目／人物匹配和行业事件归档 |
| 项目与人物 mapping | 赛道扫描、公司画像、潜在创始人发现、公开背景核验、关系路径与下一步行动建议 |
| 投资待办 | 从项目、人脉、行业动态和关键日期中整理关键节点、约见、跟进与长期未推进事项 |
| 飞书知识外挂 | 按明确指令搜索或读取 Base／Wiki／Docs／Drive，创建或编辑飞书文档，并通过飞书私聊发布 |
| Outlook 日程 | 整理主题、时间、地点与参会人，并通过已连接的 Outlook Calendar 发送日程邀请 |

## 典型使用方式

直接在 domi 客户端中用自然语言描述目标：

```text
开始录音，结束后整理纪要、投资判断和跟进事项。
研究并入库这家公司，整理项目文档并给出初步评级。
把这份创始人交流纪要整理成投资快评。
分析这份招股书的业务质量、财务质量和关键风险。
把这个项目的材料写成 IC 投委会报告。
扫描 AI4S 最近一周的重要动态，优先看重点项目和人物。
寻找具身智能方向值得认识的潜在创始人，并说明引荐路径。
同步我的待办事项，整理最近应该跟进的人和项目。
去飞书知识库查找相关材料，把最终版本发布成飞书文档。
把这个会面安排到 Outlook，并邀请我指定的参会人。
```

只要求“查一下”时，domi 默认只交付研究，不会据此推断入库或外发授权；需要写入、发送或安排日程时可以在同一任务中继续明确要求。

## 工作流为什么可靠

domi 不把多个 Skills 简单堆在一起。总控 Router 为每项任务锁定工作流、资料库后端、阶段产物、完成标准和失败恢复点：

- **任务内后端锁定**：同一项工作不会在本地与飞书之间静默切换。
- **写入前查重**：项目、人物和行业事件先搜索再新增；歧义或批量变更先确认。
- **写入后回读**：关键结构化记录和远端交付需要验证实际结果。
- **只读与写入分离**：研究请求不自动变成建档、外发或日程动作。
- **失败关闭**：权限、目标或图片导出不完整时停止在当前阶段，不用不完整结果冒充成功。
- **可恢复执行**：保留已完成产物和阶段标识，避免失败后从头重跑。

## 本地权威库，飞书作为知识外挂与发布平台

domi 默认并始终使用本地资料库：SQLite 保存结构化索引，Markdown 保存可读文档，附件保存在用户选择的 `domi工作区`。首次初始化会创建待办事项、行业研究、行业动态、项目库和人脉库；重复初始化不会覆盖用户内容。客户端或插件升级也不会清空这些运行数据。

飞书是可选知识外挂与发布平台，不是第二套管理后端。连接后仍保留 Base、Wiki、Docs、Drive、IM 和 Contact 能力，但只在用户明确要求时搜索、读取、创建、编辑或发送：

- 新用户无需手工配置 Base Token、Table ID 或固定 Wiki Space ID。
- 连接飞书不会自动创建管理 Base、迁移本地资料或改变本地主库。
- 本地 Markdown 发布到飞书前会预检，发布后回读验证标题层级、列表、表格、代码、链接、图片及内容顺序；任一图片失败时不降级为缺图的纯文本副本。
- 远端副本不会替代本地记录，本地修改也不会在没有明确指令时自动推送。
- 旧版以飞书为主库的用户，在完成导入与逐项回读验证前继续使用原 Base／Wiki／本地材料链路；全部验证后才原子切换，且不会删除旧飞书内容。

## 隐私与安全边界

运行时配置和用户数据保存在仓库之外：

```text
~/Library/Application Support/domi/
~/Documents/domi/
~/.domi/
```

- 项目资料、人脉、信源列表、录音、文字稿、数据库、飞书标识和凭据不会随插件进入 Git 或发布包。
- 用户添加的新闻、RSS、重点公众号和播客清单仅保存在本机 Application Support。
- PLAUD 是可选连接。登录由用户在 domi 专用浏览器 Profile 中完成；插件不读取日常浏览器 Profile。播客只处理公开、免费的直接音频，不读取平台 Cookie，不绕过付费、私密、HLS／DASH 或 DRM 限制。
- Outlook OAuth 由 Codex 的官方连接器管理，插件不保存令牌。
- 飞书写凭证不交给 Codex；本地 Markdown 发布由客户端 Host 根据用户的明确指令执行，Codex 只接收完成回执。

更完整的边界见 [PRIVACY.md](PRIVACY.md)。

## 推荐安装方式

普通用户直接安装 [domi Mac 客户端](https://github.com/1DeepSheep/domi/releases/latest)。客户端会安装与当前版本匹配的插件，并在升级时同步更新，无需手动复制 Skills 或修改 Codex 配置。

公开安装包同时支持 Apple Silicon 和 Intel Mac。使用前请安装并登录 Codex：

```bash
codex --version
codex login status
```

Codex 安装与登录说明见 [OpenAI Codex 官方文档](https://developers.openai.com/codex/)。

## 独立使用插件（开发者路径）

这个仓库是插件源码根目录，主要供 domi 客户端打包和插件开发使用。需要脱离客户端单独使用时，可以将仓库放入个人插件目录：

```bash
git clone https://github.com/1DeepSheep/domi-plugin.git ~/plugins/domi
```

然后按照 Codex 官方插件规范，把 `domi` 加入 `~/.agents/plugins/marketplace.json` 对应的个人 marketplace，再运行：

```bash
codex plugin add domi@personal
```

如果个人 marketplace 名称不是 `personal`，请替换为该文件顶层的 `name`。不要使用 `codex plugin install <Git URL>`：当前 Codex CLI 没有这一命令。安装后请新建一个 Codex 任务，以载入新的 Skills。

> 希望开箱即用时，请优先使用 domi 客户端自动管理插件。

## 开发与发布检查

```bash
python3 /path/to/plugin-creator/scripts/validate_plugin.py .
node scripts/public-release-check.cjs
node scripts/public-release-check.cjs --history
```

维护者可将额外敏感词写入被忽略的 `.privacy-terms.local`，或通过 `DOMI_PRIVATE_IDENTITY_TERMS` 环境变量提供；文件和变量内容不得提交。
